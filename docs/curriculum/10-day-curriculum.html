Instructor Handout · 10-Day Bootcamp

Fulfill WMS
Build a warehouse system, end to end

A ten-day, hands-on course that takes intermediate developers through the complete inventory lifecycle — from an empty warehouse to a labeled, shipped order — building on a real NestJS + Next.js + Prisma codebase.

Duration10 full days
AudienceIntermediate devs
Format40% teach · 60% lab
StackNestJS · Next · Prisma
The through-line

The spine of the course is one idea the codebase is built on: inventory correctness through an append-only ledger and database transactions. Every day builds toward it or around it. Students progress: set up a warehouse → receive stock → put it away → hold correct inventory → allocate & pick orders → pack & ship. Each day ends with a runnable vertical slice and a demo.

Prerequisites

Send before Day 1
  • Working knowledge of TypeScript, React basics, HTTP/REST, and a little SQL.
  • Installed: Node 24+, pnpm 11+, Docker Desktop, VS Code.
  • Clone the repo and run docker compose up -d once to pre-pull images before Day 1.

The 10 days

Each day: objective · topics · lab · deliverable
Day01
Foundation

Domain + Foundation

Understand what a WMS does, and get the monorepo running locally.

  • WMS domain tour: warehouse → zone → location/bin, SKU/barcode, the inbound→outbound lifecycle.
  • Monorepo architecture: pnpm workspaces + Turborepo; why a modular monolith, not microservices.
  • Repo layout tour: apps/api, apps/web, packages/database.
LabFull local bringup: docker compose up -d, migrate, seed, pnpm dev. Open web (:3000), API (:4000), Swagger. Click through seeded warehouse SEL-01.
DeliverA green local stack; everyone hits a seeded endpoint.
Day02
Data

Data model with Prisma & Postgres

Read and extend the schema; understand why the model is shaped this way.

  • Walk schema.prisma: topology, catalog, InventoryBalance, InventoryTransaction, orders, tasks.
  • Modeling rules: UUIDs, a version for optimistic concurrency, decimal quantities not floats, status transitions instead of destructive deletes.
  • Migrations vs seed; the migration workflow.
LabAdd a field to a model, generate a migration, re-seed, verify in Postgres, and read the SQL it produced.
DeliverA student-authored migration applied cleanly.
Day03
API

NestJS fundamentals

Understand how one API module is wired — modules, services, controllers, DTOs.

  • NestJS building blocks: modules, DI/providers, controllers, DTO validation, PrismaService.
  • OpenAPI / Swagger generation.
  • Guided read of the warehouse module — controller, service, DTOs.
LabBuild a new module from scratch (e.g. suppliers): model → migration → module/service/controller → DTO → visible in Swagger.
DeliverA new working endpoint the student wrote themselves.
Day04
Master data

Warehouse topology + Catalog

Build the "setup" half of the app — API and UI together.

  • Topology & catalog rules: unique location barcode per warehouse, unique SKU code, globally unique barcode, tracking policies (lot/serial/expiry).
  • Next.js App Router + TanStack Query: how the console talks to the API.
LabExtend catalog end to end (DTO → service → form → list), then wire the SKU CSV import path.
DeliverCreate a warehouse, zones, locations, and SKUs through the UI.
Day05
Kernel ★ Crux day

The Inventory Kernel

The most important day — understand and extend the transactional ledger.

  • Read the inventory-invariants ADR. Core rules: availableQty = onHand − reserved; DB constraints forbid negative or over-reserved stock.
  • Every balance change writes an InventoryTransaction row in the same DB transaction.
  • Why Redis, queues, and sockets are never the system of record.
LabTrace an adjustment UI → API → ledger. Write a service method doing a balance mutation inside a Prisma transaction that also inserts a ledger row.
DeliverA student-written stock mutation that keeps the ledger consistent.
Day06
Kernel ★ Crux day

Concurrency, idempotency & correctness

Make inventory bulletproof — the "senior engineer" day.

  • Race conditions: two workers picking the same stock. Deterministic row locking, optimistic version conflicts.
  • Idempotency keys for scanner retries; the outbox pattern for events/projections.
  • Standardized error codes: INSUFFICIENT_STOCK, DUPLICATE_SCAN, INVALID_STATE_TRANSITION.
LabWrite a test firing two concurrent allocations at one balance and prove it can't go negative. Add an idempotency check to a mutation endpoint.
DeliverA passing concurrency / idempotency test.
Day07
Inbound

Receiving & putaway

Build the first full workflow and state machine.

  • PO state machine: DRAFT → OPEN → PARTIALLY_RECEIVED → RECEIVED → CLOSED.
  • Receiving with accepted / damaged / rejected quantities, discrepancies, then putaway tasks.
LabCreate a PO → receive into staging (ledger posts) → generate & confirm a putaway that atomically moves stock to storage.
DeliverA PO fully received and put away, provable from the ledger.
Day08
Outbound

Orders, allocation & picking

The other half of the lifecycle.

  • Order flow: DRAFT → READY_TO_ALLOCATE → ALLOCATED → PICKING → PICKED → PACKED → SHIPPED.
  • Allocation: FIFO, and FEFO for expiry-controlled SKUs; reservations consume available (not on-hand) stock; short-pick / damage exceptions.
LabCreate a sales order → allocate (watch reserved rise) → generate pick tasks → confirm picks → trigger a short-pick exception.
DeliverAn order taken from creation to PICKED without touching the DB directly.
Day09
Scanner

The Scanner PWA

Build the touch/scanner front end that ties the workflows together.

  • PWA essentials: manifest, service worker, installability.
  • Keyboard-wedge scanners first, camera scanning (ZXing) as fallback. Why stock-changing commands require connectivity — no offline mutations.
LabExtend a scan flow (putaway: source → item → destination → qty) with feedback and duplicate-scan handling. Test from a phone on the LAN.
DeliverA working scan-driven workflow demoed on a device.
Day10
Ship

Pack, ship, deliveries + wrap

Close the loop and ship a portfolio-ready demo.

  • Packing verification, packages, shipment confirmation, final inventory transitions, deliveries.
  • Cross-cutting: RBAC / warehouse scoping, audit log, health/readiness, structured logging. Testing pyramid + deployment overview.
CapstoneFull end-to-end run — receive → putaway → allocate → pick → pack → ship — narrating the ledger at each step. Each student presents one feature they extended.
DeliverA live end-to-end demo + a short written architecture walkthrough.

Teaching notes & assessment

Run the room

Teaching notes

  • Days 5–6 are the crux. If students master one thing, it's the transactional ledger + invariants. Pad these if the group struggles.
  • Every day ships a vertical slice and ends with a demo — this keeps momentum visible and mirrors the repo's milestone philosophy.
  • Keep a shared "parking lot" for deep tangents so labs stay on schedule.
How to grade

Suggested assessment

50%Daily deliverables — the runnable slice each day.
30%Day-10 capstone — the end-to-end demo.
20%Individual extension — a small feature carried across the week.
